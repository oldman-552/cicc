# Agent execution and recovery rules

1. Inspect this queue, `PROJECT_STATE.json`, `DEVELOPMENT_LOG.md`, `IMPLEMENTATION_TRACKER.md`, `BLOCKERS.md` and the current working tree before choosing work. The full RCTFC v4.1 prompt is not currently in this repository; preserve known requirements and mark gaps instead of guessing.
2. Work autonomously in the current Arena session branch. Never switch, rename or push another branch. Do not restore the intentionally deleted earlier project.
3. Implement working, integrated, defensive and authorized functionality; do not fabricate evidence, results, integrations, readiness or successful tests. Preserve English, Arabic, Persian and RTL.
4. Test code, migrations and failure paths; record exact outcomes, environment constraints and untested scenarios. Keep demo mode isolated with no sensitive data.
5. Update this queue, `PROJECT_STATE.json`, `DEVELOPMENT_LOG.md`, `PROJECT_ARCHITECTURE.md`, `ACCEPTANCE_TESTS.md` and detailed documents when applicable. Set the next exact action before ending.
6. Commit and push safe verified work to the current Arena branch when requested. Never put credentials, generated databases, dependency directories or build artifacts in Git.
7. An agent response is finite. An external scheduler/orchestrator with authorized access to start new Arena Agent Mode sessions and supply the repository context is required for unattended continuation; no such mechanism is configured here. CI can run checks after pushes but does not implement features autonomously.
