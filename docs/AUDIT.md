# Development audit view

The admin-only workspace activity view loads events on demand, pages backwards using the record ID and optionally filters by an exact action string. `GET /api/audit/events?limit=50&before=123&action=source.refresh` returns at most 100 records, newest IDs first, and a `next_before` cursor when older matching records exist. The legacy `GET /api/audit` still returns the latest 100 records as a list. Both endpoints require an administrator in authenticated mode. In demo mode authentication is bypassed and the default workspace is used.

This is an operational development aid, **not an immutable, complete or tamper-evident audit system**. A database operator can alter or delete records. Unknown or otherwise unscoped authentication failures are omitted from workspace views; events attributable to a known active account's workspace may be visible there. Public source refreshes affect all workspaces but their audit entries are attributed only to the requesting workspace. Historical backfill, trusted timestamps, retention guarantees, cross-workspace security monitoring, policy enforcement and independent log export are not implemented. The ID cursor is a navigation mechanism, not proof of completeness; concurrent database changes can affect results.
