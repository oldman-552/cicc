# FIRST EPSS — limited cached enrichment

The adapter targets the official [FIRST EPSS API](https://api.first.org/epss/) at `https://api.first.org/data/v1/epss`. An administrator can refresh `epss` after collecting GitHub advisories. The adapter selects up to 30 distinct syntactically valid CVEs from the first 100 cached advisories ordered by publication, requests their current scores in one bounded query, validates the returned identifiers, model dates and 0–1 decimal values, and replaces the shared cache transactionally. A successful response can omit CVEs: absence is **unknown**, never zero or safe. An error leaves the previous cache intact and records source failure. The source is global to all workspaces.

The advisory and CVE record lists display the source's exact score and percentile as 0–1 decimal strings, the model date, collection time and the source label. FIRST describes EPSS as a model estimate of exploitation activity over the next 30 days; it is not observed exploitation, asset exposure, a priority decision or a guarantee of safety. This is not complete coverage, a continuously updated feed or a historical time series. Source data is not independently verified. Historical investigation evidence and SBOM snapshots do not incorporate EPSS estimates; there is no retroactive evidence modification.

The adapter and failure handling were tested with mocked FIRST responses only. **The live FIRST endpoint has not been contacted from this environment**, whose outbound host policy excludes it. Operational deployments need approved network access and must validate API behavior, quotas, scheduling, freshness and security. See the API documentation for the current contract. FIRST accessibility or availability is not claimed.
